## Contexte

`prompt2.txt` §3 spécifiait déjà, dès l'origine, que l'import d'un poste dont le `crm_key`
existe déjà en base doit faire un **UPDATE** (pas un ignore). En testant l'import d'un poste
avec un `crm_key` déjà présent, Damien constate que le poste existant n'est **pas mis à jour**
— écart entre la spec et le comportement réel.

**Ne suppose pas la cause** : audite le code d'import actuel (`services/importPoste.js` ou
équivalent) pour trouver précisément pourquoi le cas `crm_key` existant n'aboutit pas à un
`UPDATE`, avant de corriger. Rapporte la cause trouvée dans ton rapport de complétion.

Le principe métier confirmé par Damien : le CRM est le **référentiel maître** des postes en V1
(import CSV, ENF-12/V1) — c'est la **seule** façon de mettre à jour un poste existant dans
l'application (Passerelle ne permet aucune édition manuelle des critères d'un poste ; toute
correction passe par le CRM, réimportée ensuite).

## 2. Comportement d'import corrigé — volontairement simple

**`crm_key` inconnu (nouveau poste)** — inchangé par rapport à `prompt2.txt` §3 :
`INSERT`, `flag_create_opportunity = true`, `id_etat_poste` = "À pourvoir" (ou "Pourvu" direct
si `candidat_preaffecte = true`). `date_maj_crm` importée telle quelle si fournie
(`date_dernier_recalcul_score` reste `NULL` — un poste tout juste créé n'a encore aucune
opportunité recalculée).

**`crm_key` existant (poste déjà en base)** :
```js
// UPDATE non comparatif sur TOUS les champs (écrase, y compris les champs vides du fichier —
// comportement déjà spécifié, ne pas changer), y COMPRIS date_maj_crm. Rien d'autre à faire ici.
```

⚠️ **Ce prompt ne pose plus aucun flag et ne calcule aucune comparaison de date** — c'est
volontaire (révisé 02/09/2026 suite à échange avec Damien) : l'import se contente d'écrire les
données. C'est `prompt4.txt` §4bis (pas encore envoyé) qui, de façon totalement découplée,
compare lui-même `date_maj_crm` à `date_dernier_recalcul_score` pour décider quels postes ont
réellement besoin d'un recalcul. Ce découplage évite qu'une logique de scoring (même minimale)
se retrouve dupliquée ou désynchronisée entre le code d'import et le code de scoring.
