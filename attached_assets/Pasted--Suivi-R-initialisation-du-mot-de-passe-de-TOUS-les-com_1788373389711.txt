## Comment procéder

**N'écris pas de requête SQL avec un hash calculé à part** — utilise directement la fonction de
hash déjà existante dans le code d'authentification de l'application (celle utilisée par
l'inscription/le "mot de passe oublié"), pour garantir que le hash produit est strictement
compatible avec la vérification au moment de la connexion. Écris un petit script ponctuel (ou
une route temporaire, supprimée après usage) qui :

1. Calcule le hash de `DccTest2026!` avec la fonction de hash déjà utilisée par l'application
   (même bibliothèque, mêmes paramètres — ne réimplémente rien).
2. Met à jour `user_.mot_de_passe` (ou colonne équivalente) pour **toutes** les lignes de

3. Vérifie et rapporte le nombre exact de lignes modifiées — doit correspondre au nombre total
   de comptes `user_` en base.

## Puis, un SELECT de contrôle

Une fois la mise à jour faite, exécute et retourne le résultat de cette requête (adapte les noms
de colonnes/jointures si besoin pour coller au schéma réel) :

```sql
SELECT u.id_user, c.email, c.nom, c.prenom, u.role_applicatif, c.role AS role_contact
FROM user_ u
JOIN contact c ON c.id_contact = u.id_contact
ORDER BY u.role_applicatif, c.nom;
```
