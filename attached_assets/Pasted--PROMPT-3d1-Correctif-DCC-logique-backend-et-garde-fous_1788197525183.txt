## 2. Garde-fou — changement d'onglet en cours d'édition (A21, remplace l'ancien point sur le bandeau)

Sur l'écran détail candidat (et poste, même composant), si un onglet est en mode édition avec des
modifications non enregistrées, et que l'utilisateur tente de **naviguer vers un autre onglet**
(ou de quitter l'écran), affiche une **popup applicative de confirmation** (pas de `confirm()`
JavaScript natif — voir §3 ci-dessous, même principe) : *"Vous avez des modifications non
enregistrées sur cet onglet. Voulez-vous les abandonner ?"* avec deux boutons — "Continuer
l'édition" (annule la navigation) et "Abandonner les modifications" (quitte l'onglet, perd les
changements non sauvegardés).

## 4. Validation des champs obligatoires avant soumission de la fiche de vœux

`soumettre_voeux_provisoire()` et `soumettre_voeux_definitif()` doivent **vérifier côté backend**
(pas seulement côté frontend) que tous les champs obligatoires de la fiche de vœux sont renseignés
avant d'accepter la soumission — retourne une erreur 400 explicite listant les champs manquants
sinon. Règle : **tous les champs sont obligatoires par principe** ; pour un champ à liste de
valeurs (langues, compétences, milieu, logement, destinations...), "obligatoire" signifie **au
moins une valeur sélectionnée**, pas nécessairement toutes.

## 6. Bug — "Mot de passe oublié" (Correctif DCC A37)

Une candidate importée (Anne Girard, compte `user_` confirmé existant) a essayé le lien "mot de
passe oublié" sans succès. **Le log fourni ne montre aucune requête backend correspondant à cette
action** (juste un `GET /` → 404 sans rapport) — ça exclut a priori un problème d'envoi d'email
(SMTP), puisqu'aucune requête n'a même atteint le serveur pour déclencher une tentative d'envoi.
Piste la plus probable : le lien/bouton "Mot de passe oublié" côté frontend n'est pas câblé sur une
route API existante, ou pointe vers une URL de route qui n'existe pas (d'où potentiellement le
`GET /` 404 observé, si un routing SPA mal configuré retombe sur la racine).

**À faire** : reproduis le clic sur "Mot de passe oublié" en observant le réseau (Network tab) et
les logs serveur au même moment, identifie la route (ou l'absence de route) réellement appelée, et
corrige. Si la route existe bien et échoue spécifiquement à l'étape d'envoi d'email (SMTP), alors
seulement c'est un problème d'infrastructure à traiter plus tard sur le serveur de production — ne
pas s'arrêter à cette hypothèse sans l'avoir vérifiée, le log actuel ne la confirme pas.

## 7. Pièces jointes — lien cliquable + espace de stockage configurable (Correctif DCC A22)

**Bonne nouvelle en réexaminant le schéma** : `etape.url1_piece_jointe` et `url2_piece_jointe`
sont **déjà** des colonnes `VARCHAR(250)` qui stockent une URL, pas un fichier binaire — le modèle
que Damien voulait (URL en base, fichier ailleurs) est donc déjà en place côté candidat. Le "non
cliquable" observé (onglet "Progression et documents") est donc très probablement un simple bug
d'affichage frontend : l'URL est affichée en texte brut au lieu d'être rendue comme un vrai lien
`<a href="..." target="_blank">`. **Corrige cet affichage** partout où `url1_piece_jointe`/
`url2_piece_jointe` sont montrés (actuellement : onglet "Progression et documents", écran
candidat). La refonte plus large en table `piece_jointe` (0 à N pièces par étape, cf. discussion
A22) est **reportée à prompt4** (Opportunité) — pas nécessaire pour corriger ce bug précis.

**Espace de stockage — paramètre configurable** : Damien n'a pas encore de solution de stockage
définitive (dépend du serveur de déploiement prod/préprod, pas encore connu). En attendant, ajoute
une variable d'environnement pointant vers un espace de stockage temporaire (un dossier partagé,
ex. Google Drive) :
```
# .env.example (backend)
PIECE_JOINTE_STORAGE_URL=https://drive.google.com/drive/folders/XXXXXXXXXXXXXXXXXXXXXXXX?usp=sharing
```
Affiche cette URL comme un **bouton/lien cliquable** ("Accéder à l'espace de stockage partagé")
dans la popup d'ajout de pièce jointe (pattern générique, conception.md §6.1.2) — le recruteur y
dépose son fichier manuellement, récupère le lien de partage généré par Google Drive (ou l'outil
utilisé), puis le colle dans le champ URL de la pièce jointe. **Aucune intégration API réelle avec
Google Drive n'est nécessaire** — c'est un simple rappel visuel pointant vers un dossier, pas un
upload automatisé.

⚠️ **Le jour du déploiement sur un autre environnement (préprod/prod), il faudra changer la valeur
de `PIECE_JOINTE_STORAGE_URL`** dans les variables d'environnement du nouvel hébergement — aucune
action de code nécessaire, seulement une reconfiguration.
